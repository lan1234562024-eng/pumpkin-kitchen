# 演示视频录制提纲

目标时长 **2 分 55 秒以内**。这是录制方案，不是已完成视频或既有测试结果。最终字幕、分数和接入状态以实际录制为准。

## 分镜与解说

| 时间 | 画面 | 解说或字幕 |
|---|---|---|
| 0:00–0:12 | 项目标题与厨房全景 | “南瓜厨房：邀请自己的 AI，和你一起接单、备菜、做饭。” |
| 0:12–0:35 | 从参赛页打开网页试玩，展示移动、互动与演示标签 | “打开网页即可试玩。这里的队友由规则驱动，用来熟悉玩法。” |
| 0:35–0:45 | 切换完整本地版，显示大厅和真实 AI 席位已连接 | “完整本地版通过 MCP 连接用户自己的 AI。它能观察当前局面并选择任务。” |
| 0:45–2:15 | 录制一局约 90 秒的实际配合，展示人类与 AI 各自做菜、交接和结算 | 按实际动作少量标注“玩家切配”“AI 接单 / 备料”“交接”“交付”。不要预写成功分数。 |
| 2:15–2:35 | 根据实际素材展示控制状态、接管或停止；若本局已结束，则展示结算和下一局等待状态 | “游戏执行具体动作，AI 决定下一步。用户始终可以接管，结束后由用户决定是否继续。” |
| 2:35–2:50 | 展示干净的仓库首页与 AI-START-HERE.md | “下载完整代码，把接入指南交给自己的 AI，即可按环境完成配置。” |
| 2:50–2:55 | 项目标题与仓库 / 试玩入口 | “和自己的 AI，一起玩。” |

## 录制要求

1. **真实 AI 片段必须来自实际 MCP 控制。** 保持可见的席位状态；如果接入失败，先修正或重录，不能用演示队友画面替代。
2. 尽量保留一局完整过程。需要剪辑、倍速或跨局组合时，在画面上明确标注；不要把剪辑造成的连续动作描述为实际无延迟。
3. 工具响应只展示必要摘要。控制凭据、账号资料、私人聊天、系统通知、绝对个人路径和客户端身份信息应在录制前隐藏或在导出前裁除。
4. 如果工具区不适合公开，可以只录游戏画面，并添加依据真实调用整理的说明字幕；这些字幕不得伪装为原始实时工具输出。
5. 规则演示片段保留“演示队友 / 非真实模型”标识；真实 AI 片段保留明确的连接状态。
6. 使用实际结果，不承诺每局都能完成多少份，不隐藏影响演示理解的关键失败。

## 导出前检查

- 总时长不超过 3 分钟，字幕与游戏字迹可读。
- 两种队友的身份清楚，片段来源与字幕一致。
- 没有私人称呼、账号资料、凭据、未公开地址或具体模型名称。
- 开头能看懂“这是人与自己的 AI 协作”，结尾能找到作品入口。
- 视频能正常播放；提交表中的视频链接确实指向最终文件。
