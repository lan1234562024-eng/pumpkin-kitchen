# 南瓜厨房

**和自己的 AI 一起接单、备菜、做饭。**

这是一个约 90 秒一局的双席位协作游戏：你操作玩家角色，自己的 AI 通过 MCP 观察局面、选择任务并操作队友角色。游戏负责移动、切配、烹饪与计分，AI 负责决定下一步做什么。

**体验入口：**[网页试玩](https://lan1234562024-eng.github.io/pumpkin-kitchen/) · [下载完整本地版 ZIP](https://github.com/lan1234562024-eng/pumpkin-kitchen/archive/refs/heads/main.zip) · [查看代码仓库](https://github.com/lan1234562024-eng/pumpkin-kitchen)

网页试玩中的演示队友**不是大模型**。真实 AI 接入使用完整本地版；网页试玩不提供远程 AI 服务，也不要求填写模型 API 密钥。

## 把接入工作交给自己的 AI

下载并完整解压代码，把 [AI-START-HERE.md](AI-START-HERE.md) 交给能读取文件、操作本地终端的 AI，然后发送：

> 请先阅读 AI-START-HERE.md，检查环境，完成本地启动和 MCP 接入。需要我操作的步骤再提醒我；连接成功后停在大厅，等我开始游戏。

只有聊天能力的 AI 也可以依据说明逐步指导你。接入说明见 [docs/AI-CONNECTIONS.md](docs/AI-CONNECTIONS.md)。

## 手动启动完整本地版

1. 安装 Node.js 24 或更新版本，并确认 `node --version` 与 `npm --version` 可用。
2. 在包含 `package.json` 的项目根目录打开终端，执行：

   ```sh
   npm ci
   npm run dev
   ```

3. 保持终端打开，在浏览器访问 **http://127.0.0.1:5173**。
4. 将自己的 AI 客户端连接到本地 MCP：**http://127.0.0.1:5230/mcp**。也可以按接入说明使用 stdio 桥。
5. 让 AI 只读检查规则和局面，确认已取得 AI 席位后，由你点击“开始一局”。开局后告诉 AI“开了”，让它重新取得当前回合上下文。

首次 `npm ci` 需要联网下载依赖。结束时在启动终端按 **Ctrl+C**。本地服务使用 5173 与 5230 端口；如果已开着另一份游戏，先确认并关闭自己的旧启动窗口，避免重复启动。

## 网页模式的开发与部署

`npm run dev:demo` 可在本机启动独立演示；`npm run build:demo` 生成静态网站到 `dist`。仓库附有 GitHub Pages 工作流，操作见 [发布说明](docs/DEPLOYMENT.md)。Windows 完整本地版也可双击根目录 `START.cmd`，它会检查端口并在首次运行时安装依赖。

## 怎么玩

- **WASD / 方向键**移动，**E**或页面互动按钮操作工位；也可以点击地面或工位前往。
- 到接单台接单，在订单倒计时内完成并交付。
- **贝贝南瓜沙拉**：南瓜切配并煮熟，与切好的黄瓜装在同一碗中。
- **奶油南瓜汤**：南瓜切配并煮熟，在锅里加入奶油继续烹饪，最后盛碗。
- 锅放在灶上会持续烹饪，端走会暂停；熟菜不会着火。清理口只清除内容物。
- 通过交接台或柜台转交物品，也可以从界面接管队友。规则演示与真实 AI 接入均应尊重你的接管。

## AI 队友怎样行动

AI 使用 `game_brief` 和 `game_observe` 读取实际规则与局面，通过 `game_join` 取得自己的席位，优先使用 `game_task` 完成明确的站点任务。客户端可能给工具名添加前缀，以当前实际暴露的工具为准。

模型不逐帧发送按键。移动与加工由游戏执行，动作完成、目标变化和控制权变化都会返回给 AI，由它继续决定下一步。

## 当前边界

- 网页试玩与本地游戏是不同的运行实例；网页试玩不能连接到某个本地 AI 席位。
- 完整本地版默认仅监听本机。云端 AI 客户端需要用户自己配置受保护的远程连接，参见接入说明。
- AI 的思考、工具审批与请求往返会影响配合节奏，动作间可能存在空档。
- AI 控制租约会在 30 秒无有效控制请求后过期；开新局或被人工接管也会改变控制上下文。过期动作不得重放。
- 游戏不在聊天之外托管后台 AI，不包含跨设备多人房间、语音服务或模型 API 代付。
